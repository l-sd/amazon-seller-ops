# 竞品分析：同一购买任务下比较具体商品

## 定义可比范围

先明确本站点、自有产品或目标商品、买家使用任务、规格/套装、价格带和研究目的。区分直接竞品、替代方案与头部参考；不能仅因同属大类就一并排名。用户没指定数量时，以可核查资料为准，先完成小样本。可先搜索候选，再记录排除理由。

无自有产品时做品类对比，明确不能声称找到“自有页面的缺陷”。同一家族变体标父/子 ASIN 和实际选中款，避免重复计算为独立品牌；评论与评分可能家族共享，不能全归到选中变体。

## 采集证据

每条记录：站点、ASIN、具体变体/套装、URL、带时区的观察时间、配送地区、来源类型和可访问状态。保留与结论直接相关的价格/规格/页面事实；无需复制整页文案或图片。

| 维度 | 记录方法与限制 |
|---|---|
| 价格与 Offer | 明确标价/折后价、优惠券条件、配送与会员限制、套装数量。能确认条件才算到手价或单位价；不自动扣所有优惠券。缺货价格不直接作为可购买价 |
| 产品 | 材质、尺寸、容量、适配、包装数量、使用限制；“卖家宣称”和“已验证事实”分开 |
| 页面 | 标题、五点、图片说明、A+和视频是否回答购买问题。未见到内容记不可访问，不默认不存在 |
| 客户体验 | 可访问评论按近期/星级/变体分层抽样，说明排序和样本量。记录日期、变体、问题与原链接；不收集无关个人信息 |
| 搜索与竞争 | 区分 Sponsored 广告位与自然位置，记录关键词、地区、时间和页面上下文。单次位置不能当稳定排名或曝光份额 |
| 需求线索 | BSR 需类目和时间；销量提示需原文字与时间范围。第三方估算保留工具、窗口、地区和方法限制，不能改成实际销量 |

网页被限流/登录阻挡就保留缺口，换可用页面、用户截图或已有导出，不绕过。付费工具只使用用户已有授权的数据，不新增订阅。

## 分析和交付

1. 做规格归一后的竞品矩阵，不直接平均不同容量/套装价格。对不可比项解释原因。
2. 把评论编码为使用场景、购买动机、期望落差、产品故障、适配/尺寸和页面信息问题；抽查原文和反例。样本占比只代表该样本，不称市场发生率。
3. 建立“买家问题 → 原始证据 → 产品/页面缺口 → 建议 → 验证方法”的对应。没有产品实测，不宣称能解决竞品缺陷。
4. 输出直接竞品与差异点、优先验证的问题、可落地的标题/五点/图片任务草稿。参数须由自有产品资料支持，不能把竞品参数搬到自己商品；不抄文案、图或商标。
5. 重复观察时按同站点、变体和配送地区比价，使用 `scripts/compare_snapshots.py`。新出现记录叫“新增观察对象”，缺失叫“未复查到”，不能说新品上市/下架。价格口径或币种变了则不可直接算价格涨跌。

实务依据：Helium 10 用价格、页面与表现变化组织竞品观察；Jungle Scout 先界定竞争集合再作市场/商品对照。仅借鉴步骤，不沿用商业工具的预测数值和营销承诺。[T1/T2，见 sources.md]
