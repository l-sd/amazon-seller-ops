# ASIN 反查 → 词库 → 每日排名跟踪 → 复盘

## 数据获取与工具

用户所说“西柚”按检索结果优先理解为西柚洞察（原西柚找词）；若提供的域名不同，以实际网站为准。使用现有授权的连接或用户导出；不要自建爬虫绕过验证，也不订阅付费套餐。官方宣传页可见 MCP，但本项目未配置或验证该连接，不能直接声称能调用它。来源 T3–T6 见 sources.md。

分清两类输入：**ASIN 反查导出**用于发现候选词；**排名监控记录**才用于日序列。反查列表没有出现某词，可能是覆盖时间/搜索深度/数据库更新原因，不能据此说 ASIN 未收录。数据从监控开始积累，不能补造开始监控前的每天排名。

## 首次建库或定期扩词

1. 确认站点、自己的具体子 ASIN、父子关系、核心场景和可比竞品。多个变体分别记录，父体汇总不冒充某子体表现。
2. 用自有/竞品 ASIN 反查词，记录工具、提取时间、报告窗口与原始来源。保留原词，按大小写和空白做去重；不擅自把不同词干、单复数、词序或标点合并为同一搜索词。
3. 按商品事实人工核查相关性，分核心、属性、场景、长尾等意图；记录排除依据。品牌/商标和不适配词标记用途限制，不能把竞品品牌词自动写进自己的页面。
4. 将“自己的已有词、竞品覆盖而我未观察到的词、双方都有但排名差异的词”分组。反查未观察到不等于真正没有；工具估计搜索量/流量份额保留原口径，不当实际曝光。
5. 结合相关性、推广阶段、自己的广告转化证据、工具额度选择监控词，记录优先级和理由。大词不一定优先，默认不设统一搜索量/排名门槛。候选词库模板为 `assets/keyword-pool.csv`。

## 每次更新排名日报

- 优先沿用同一工具、站点、ASIN、关键词、自然/广告类型、绝对排名定义、设备、配送地区和采样规则。换来源或规则需分序列，不拼接成连续趋势。
- 保存**数据实际采集时间**与导出时间的区别；同一旧采集结果再次导出不是新一天的观测。卖家精灵帮助说明监控存在滚动更新，不能假定所有词在零点统一刷新。
- 自然绝对排名、广告位排名/类型、ABA 搜索频率排名分开。页码/页内位置无法在未知每页结果数时折算绝对排名。搜索频率排名反映词的市场排序，不是某 ASIN 在该词下的位置。
- 区分找到排名、确认超出采集范围、未采集、采集失败/不可访问。`0`、`-`、`>306` 等先查导出定义，不自动变成整数。超范围要记录实际搜索上限，未观察到不能说已下架或掉词。
- 默认每日取该采样规则下最后一次采集；原始日内记录全保留。固定时点/均值/最好值是不同规则，不能混用。前日和上周同日无可比记录就留空，不能拿上一次记录冒充昨日。
- 排名数值越小越靠前，定义“改善名次=旧排名−新排名”。输出逐日排名表、历史明细和变化清单，标明缺日、未采集和首次观察。新词首次观察不叫“新收录”。

脚本示例（仓库根目录）：

```powershell
& 'D:\venvs\ecommerce-analytics-agent\Scripts\python.exe' '.agents\skills\amazon-seller-ops\scripts\track_keyword_ranks.py' --input 'private_data\today.csv' --history 'outputs\yesterday\rank_history.csv' --data-kind user-provided --output-dir 'outputs\ranks-today'
```

首次不传 `--history`。`--input` 可传多份；原始表头不同用 `--mapping` JSON 按文件名映射到模板字段。模板是本项目标准格式，不宣称是西柚实际导出格式。真实表首次需检查采集时间、状态码和排名定义再映射，不把所有缺失值当零。

## 看变化之后做什么

先检查采集/地区/时间差与连续趋势，再结合曝光、点击、广告花费与转化、库存、价格、配送、页面修改日志。自然位提升不等于盈利，广告位变动不直接等于出价导致。优先输出核心词变化、是否需要复查、可查的数据和建议动作；调整竞价、否定或改页面须另有执行授权。

用户要求“每天更新”时，可按新导出和上一版历史逐次生成新文件；尚无持续数据源或调度时不说已自动运行。只有明确要求建立定时任务时才走当前环境的自动化工具，并确认有合法可持续数据来源和额度。排名提醒应按业务阈值/跨档与持续性筛选，同一事件不重复提醒，未变化保持安静。
